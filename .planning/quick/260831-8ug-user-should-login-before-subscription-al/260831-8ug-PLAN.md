<objective>
Put a Google sign-in gate in front of the two paid membership plans, back it with a real
Vercel Postgres database, and collect the Hard Copy delivery address in the app instead of
in Stripe Checkout.

Purpose: today anyone can click "Become a member" and land in Stripe with no account behind
the purchase, and Hard Copy addresses live only in Stripe with no way to query who ordered
what. This adds the missing identity and storage layer without touching the free Reader
tier or the existing entitlement check.

Output: a users/addresses schema in Vercel Postgres, a hand-rolled Google OAuth flow over
four small serverless routes, an HMAC-signed httpOnly session cookie, a login gate enforced
on both the client and the server, and an in-app address form that replaces Stripe's
shipping_address_collection for Hard Copy.
</objective>

**lib/db.js** — the only place that knows the schema.
Export a lazy `sql` getter, NOT a module-scope `neon(...)` call — this project's own convention
(see the comment in `lib/stripe.js`) is that every module reading an env var does so lazily
inside a function, never at module scope, because a module-scope throw surfaces on Vercel as a
bare `FUNCTION_INVOCATION_FAILED` with nothing in the logs. Memoize it in a module-level
variable so `neon()` is constructed once per warm instance:
```js
import { neon } from '@neondatabase/serverless';
let _sql;
function getSql() {
  if (!_sql) {
    const connectionString = process.env.DATABASE_URL || process.env.POSTGRES_URL;
    if (!connectionString) throw new Error('DATABASE_URL (or POSTGRES_URL) is not set');
    _sql = neon(connectionString);
  }
  return _sql;
}
export const sql = (...args) => getSql()(...args);
sql.query = (...args) => getSql().query(...args);
```
This wrapper lets every call site below keep writing `` sql`...` `` and `sql.query(...)` exactly
as if `sql` were the real Neon function, while the actual `neon()` construction (and its env-var
read) is deferred to first use. Export `SCHEMA_SQL` as an array of two DDL strings, in this
order:

  users: `id bigint generated always as identity primary key`, `google_sub text not null unique`,
  `email text not null`, `name text`, `picture text`, `created_at timestamptz not null default now()`,
  `last_login_at timestamptz not null default now()`. Wrap in `create table if not exists`.

  addresses: `id bigint generated always as identity primary key`,
  `user_id bigint not null unique references users(id) on delete cascade`,
  `full_name text not null`, `line1 text not null`, `line2 text`, `city text not null`,
  `region text`, `postal_code text not null`, `country char(2) not null`, `phone text`,
  `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()`.
  Wrap in `create table if not exists`. The `unique` on user_id is deliberate — one delivery
  address per member, and it gives the upsert a conflict target without a second index.

Export `ensureSchema()`: memoised in a module-level promise so the DDL costs one round trip
per warm instance and nothing on subsequent calls; run each statement with `sql.query(stmt)`
(the tagged template is for parameterised values, `.query()` for these fixed DDL strings).
On failure, reset the memo to null before rethrowing, otherwise a single cold-start blip
would poison the instance for its whole life. Explain that reasoning in a comment.

Export `upsertUser({ sub, email, name, picture })`: a single `insert ... on conflict (google_sub)
do update set email = excluded.email, name = excluded.name, picture = excluded.picture,
last_login_at = now() returning id, email, name`. The Neon tagged template returns the row array
directly (NOT `{ rows }` — that shape was specific to the deprecated `@vercel/postgres` package),
so write `const rows = await sql\`...\`; return rows[0];`. Comment why this is an upsert rather
than a select-then-insert: sign-in is the only write path and a race between two tabs must not
create two accounts.

Add `"db:setup": "node --env-file=.env.local scripts/db-setup.mjs"` to package.json scripts.

**lib/session.js** — the session cookie, and the OAuth state cookie.
Export `SESSION_COOKIE = 'ladidier_session'` and `OAUTH_STATE_COOKIE = 'ladidier_oauth_state'`.
These names must not collide with the existing `ladidier_member_session` from lib/membership.js;
the two systems are independent and a member who signs out of Google keeps their paid access.
Import `readCookie` from `./membership.js` rather than writing a second cookie parser.

Session value format: `base64url(JSON.stringify(payload)) + '.' + base64url(hmac)`, where the
payload is `{ uid, email, name, exp }` and `exp` is a unix-seconds expiry 30 days out. Build
the HMAC key lazily with `crypto.subtle.importKey('raw', ..., { name: 'HMAC', hash: 'SHA-256' },
false, ['sign'])` from `process.env.SESSION_SECRET`, throwing a named error when the secret is
absent — same lazy pattern and same reasoning as `getStripe()`.

Export `signSession(payload)` and `readSession(cookieHeader)`. `readSession` returns the
payload or null; it must recompute the HMAC and compare with a constant-time loop (accumulate
a XOR difference over all bytes and test once at the end — a short-circuiting `===` on the
signature leaks how much of a forgery was correct). It must also reject an expired `exp`.
Any malformed input returns null rather than throwing; a garbage cookie is an anonymous
visitor, not a server error.

Export `sessionCookie(value)` and `clearSessionCookie()` producing Set-Cookie strings with
`Path=/; HttpOnly; Secure; SameSite=Lax` (clear uses `Max-Age=0`). Export `stateCookie(value)`
and `clearStateCookie()` the same way but `Path=/api/auth; Max-Age=600`. SameSite must be Lax
on both, not Strict: the browser arrives back from accounts.google.com as a cross-site
top-level GET, and Strict would withhold the state cookie and break every sign-in. Say that
in a comment so nobody "hardens" it later.

**api/auth/google.js** (`export async function GET`) — start the flow.
Read GOOGLE_CLIENT_ID and SESSION_SECRET; if either is missing, log the specific name and
return a 500 with an opaque message. Read `?returnTo=` and accept it only if it matches
`/^[a-z]+$/` (these are hash route names such as `subscribe`), defaulting to `subscribe` —
this is what stops the parameter being used as an open redirect. Mint a nonce with
`crypto.randomUUID()`. Put `${nonce}:${returnTo}` in the state cookie and send only the nonce
as the `state` query parameter, so the value the attacker can see and edit carries nothing we
trust. Derive the origin from `x-forwarded-proto` / `x-forwarded-host` exactly as
api/checkout.js does. Return a 302 to `https://accounts.google.com/o/oauth2/v2/auth` with
`client_id`, `redirect_uri=${origin}/api/auth/callback`, `response_type=code`,
`scope=openid email profile`, `state`, `access_type=online`, `prompt=select_account`, and the
state Set-Cookie header.

**api/auth/callback.js** (`export async function GET`) — finish the flow.
Read `code` and `state` from the URL and the state cookie; on any mismatch, missing value, or
missing code, redirect to `/?auth=failed#subscribe` with the state cookie cleared. Never leak
which of the checks failed.
Exchange the code at `https://oauth2.googleapis.com/token` with a form-encoded POST carrying
`code`, `client_id`, `client_secret`, `redirect_uri` (byte-identical to the one sent in
api/auth/google.js — Google compares them) and `grant_type=authorization_code`.
Split the returned `id_token` on `.` and base64url-decode the payload. Validate `aud` equals
GOOGLE_CLIENT_ID, `iss` is `accounts.google.com` or `https://accounts.google.com`, `exp` is in
the future, and `email_verified` is exactly `true` — an unverified Google email is not proof
of anything. The signature is deliberately not checked; add a comment recording why: the token
came straight back from Google's own token endpoint over TLS in a server-to-server call, which
is the case Google's documentation explicitly exempts from local verification. If any check
fails, redirect to `/?auth=failed#subscribe`.
Then `await ensureSchema()`, `upsertUser({ sub, email, name, picture })`, sign a session, and
302 to `/#${returnTo}`. Two cookies must go out at once (set session, clear state), so build
the response with `new Headers()` and `headers.append('Set-Cookie', ...)` twice — the plain
object form of the headers argument can only carry a single Set-Cookie and would silently
drop one.

**api/auth/me.js** (`export async function GET`) — `readSession` on the cookie header, return
`{ user: { id, email, name } }` or `{ user: null }`, always with
`Cache-Control: private, no-store` (the same PRIVATE constant idea as api/entitlement.js —
this answer is per-visitor and must never reach a shared cache).

**api/auth/logout.js** (`export async function POST`) — return `{ ok: true }` with
`clearSessionCookie()`. It does not touch the member cookie: signing out of Google is not
cancelling a subscription.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /api/auth/* | Untrusted query parameters and cookies arrive here; the OAuth `code` and `state` are attacker-influencable. |
| browser -> /api/checkout, /api/address | The only thing standing between a visitor and a paid entitlement or another member's address row. |
| our server -> accounts.google.com / oauth2.googleapis.com | Outbound TLS; the identity assertion crosses back over it. |
| our server -> Vercel Postgres | First write path this project has ever had; all visitor-supplied strings end up here. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-Q8UG-01 | Spoofing | `lib/session.js` session cookie | critical | mitigate | HMAC-SHA256 over the payload with SESSION_SECRET, verified with a constant-time compare, plus an `exp` check. A forged or edited cookie fails verification and is treated as anonymous. |
| T-Q8UG-02 | Tampering | `api/auth/callback.js` OAuth callback | high | mitigate | Single-use `state` nonce held in an httpOnly `Path=/api/auth` cookie with a 600s Max-Age, compared to the returned `state`; mismatch aborts the sign-in. Blocks login-CSRF and code injection. |
| T-Q8UG-03 | Elevation of Privilege | `api/checkout.js` | critical | mitigate | The login gate is enforced server-side with a 401 before any Stripe call; the client-side branch in SubscribePage is convenience only. Verified by a cookie-less curl in Tasks 5 and 7. |
| T-Q8UG-04 | Tampering | `api/address.js` POST | high | mitigate | `user_id` is taken from the verified session exclusively; any `user_id` in the request body is ignored. A member cannot write an address onto another member's account. |
| T-Q8UG-05 | Information Disclosure | session and state cookies | high | mitigate | `HttpOnly; Secure; SameSite=Lax` on both, so page scripts cannot read them and they are not sent on cross-site subrequests. Lax (not Strict) is required for the top-level GET return from Google. |
| T-Q8UG-06 | Spoofing | Google id_token claims | high | mitigate | Validate `aud` against GOOGLE_CLIENT_ID, `iss`, `exp`, and require `email_verified === true`. The token is only trusted because it was fetched directly from Google's token endpoint over TLS, not read from a redirect. |
| T-Q8UG-07 | Tampering | SQL in `lib/db.js`, `api/address.js` | high | mitigate | All values pass through the `@neondatabase/serverless` tagged template (via `lib/db.js`'s `sql` wrapper), which parameterises. `sql.query()` is used only for the fixed DDL strings, which contain no visitor input. |
| T-Q8UG-08 | Denial of Service | `api/address.js` field sizes | medium | mitigate | Every field trimmed and capped (200 chars, 40 for phone) before it reaches Postgres; country must be a member of the server's own allow-list. |
| T-Q8UG-09 | Information Disclosure | `/api/auth/me`, `/api/address` GET | medium | mitigate | `Cache-Control: private, no-store` on both, matching api/entitlement.js, so a per-visitor answer can never be served from a shared CDN cache. |
| T-Q8UG-10 | Elevation of Privilege | `?returnTo=` on `/api/auth/google` | medium | mitigate | Accepted only when it matches `/^[a-z]+$/` and defaulted to `subscribe`; the value travels in the httpOnly state cookie, not in the attacker-visible `state` parameter. Closes the open-redirect. |
| T-Q8UG-SC | Tampering | npm install of `@neondatabase/serverless` | high | mitigate | No RESEARCH.md legitimacy audit exists, so the package was treated as [ASSUMED]: Task 1 verified publisher (official Neon/Vercel), scope spelling, license, and maintenance activity on npmjs.com, surfaced a deprecation finding on the originally planned `@vercel/postgres`, and got explicit user approval to switch before any install ran. Resolved 2026-08-31. |
| T-Q8UG-11 | Repudiation | Stripe subscription <-> member linkage | low | accept | `metadata.user_id` on the Checkout Session is the only audit link and it is write-only today; `api/webhook.js` still logs rather than fulfils. Accepted because entitlement remains Stripe's answer, exactly as it is now, and no new claim depends on this trail. |
| T-Q8UG-12 | Denial of Service | `ensureSchema()` on cold start | low | accept | One extra DDL round trip per warm instance. Accepted over a build-time migration step because it removes the "someone forgot to migrate" failure mode entirely; the memo is reset on failure so a transient error does not poison the instance. |
