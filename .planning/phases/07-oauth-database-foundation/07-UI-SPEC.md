# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 7's UI footprint is narrow by design (see CONTEXT.md `<domain>`): a small
sign-in indicator in the main site `Nav` (`src/components.jsx`), and a sign-in/sign-out row on
the existing `SubscribePage` (`src/pages.jsx`). No new pages, no account/profile page (Phase 9),
no address form (Phase 9). This contract covers exactly those two surfaces plus the (copy-less)
sign-in-failure path.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — custom hand-built CSS design system (`src/styles.css`, 1279 lines) |
| Icon library | none — the site uses text glyphs (e.g. `→`) and CSS shapes, no icon package |
| Font | Manrope (`--sans`/`--display`, primary), JetBrains Mono (`--mono`, used for `nav-right`/eyebrow labels), Instrument Serif (`--serif`, editorial toggle — not used by this phase's elements) |

**Why no shadcn:** `components.json` is absent, and the project is explicitly zero-dependency by
taste — the reused draft plan states outright: *"This project is zero-dependency by taste. The
ONLY new package is `@neondatabase/serverless`... no framework, no router"* (260831-8ug-PLAN.md,
`<constraints_for_every_task>`). The site already has a complete, mature custom design system
(CSS custom properties, `.btn`/`.btn.ghost`/`.btn.solid`, `.muted`, `.eyebrow`, `.mono`, nav
patterns). Introducing shadcn here would contradict an explicit, standing project convention
rather than fill a real gap — this phase's two small additions reuse existing classes/tokens
instead. Registry safety gate: not applicable.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` (`--ivory` #FFFFFF light / `#0B0907` dark) | Page background — unchanged |
| Secondary (30%) | `var(--cream)` / `var(--bg-2)` / nav backdrop (`color-mix(in srgb, var(--bg) 80%, transparent)` + blur) | Nav bar surface, plan cards — unchanged |

**Accent reserved for (this phase explicitly does NOT use gold):** The Nav sign-in indicator and
the Subscribe page sign-in/sign-out row use only neutral tones — `var(--fg)`/nav-link opacity
convention for the Nav element, and `.muted` (`var(--mute)`) + `.btn.ghost` (neutral, transparent,
underline-on-hover) for the Subscribe row. Gold stays reserved for what it already marks
elsewhere on this page: the selected billing-interval toggle, the "Most chosen" plan-card
accent, and `.btn.solid`'s hover state. Do not apply gold to any sign-in/sign-out element —
doing so would visually promote authentication above the page's actual purchase CTAs.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Nav sign-in link (signed out) | "Sign in" |
| Nav indicator (signed in) | `{user.name \|\| user.email}` — prefer name over email (shorter, more readable in the constrained `.nav-right` space); fall back to email when Google returns no name |
| Subscribe row CTA (signed out) | "Sign in with Google" (`.btn.ghost`), paired with muted label "Members sign in with Google." |
| Subscribe row label (signed in) | "Signed in as {user.email}" |
| Subscribe row CTA (signed in) | "Sign out" (`.btn.ghost`) |
| Empty state | Not applicable — no list/form/media element exists in this phase's scope (Nav indicator and Subscribe row are both `nav`/`interactive-control` kinds per the UI-consideration probe's element classification, which does not raise "empty") |
| Error state | **No visible copy, by design.** A failed sign-in (state mismatch, denied consent, invalid token claims) redirects silently to `/?auth=failed#subscribe` with the state cookie cleared — no banner, no toast, no inline message (CONTEXT.md D-07, locked). Do not add error copy beyond this. |
| Destructive confirmation | Not applicable — this phase has no destructive action. Signing out is non-destructive and instantly reversible (sign in again); it does not delete data, cancel a subscription, or require confirmation. |

## Element Specifications

### Nav sign-in indicator (`src/components.jsx`, inside `.nav-right`)

New element, not covered verbatim by the draft plan (CONTEXT.md D-04 adds this beyond the
draft's Subscribe-page-only design). Sits alongside the existing `#search` link and the
unrelated `EN · USD` stub (D-05 — do not repurpose that stub).

```jsx
{authReady && (
  user ? (
    <a
      href="#subscribe"
      onClick={(e) => { e.preventDefault(); setRoute("subscribe"); }}
      className="nav-signin"
      title={user.email}
    >
      {user.name || user.email}
    </a>
  ) : (
    <a href={`/api/auth/google?returnTo=${returnTo}`} className="nav-signin">
      Sign in
    </a>
  )
)}
```

- While `!authReady`, render nothing in this slot — matches the existing pattern used for
  `TreasureProgress` (renders nothing until state is known) and prevents a "Sign in" flash for
  an already-signed-in visitor.
- Reuses the existing plain `<a>` nav-link visual treatment (`.nav a`: `opacity: .82`, hover
  `1`) — do not style this as a `.btn`; it should read as a nav-level utility link, consistent
  with `#search` and `EN · USD`.
- New CSS class `.nav-signin` (append near the existing `.nav a, .nav button` rules in
  `src/styles.css`) handles the overflow consideration below:

```css
.nav-signin {
  display: inline-block;
  max-width: 140px;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  vertical-align: middle;
}
```

- Placement: after `#search`, before the `Subscribe` nav item (reads Search → Sign in →
  Subscribe → `EN · USD`) — exact ordering is Claude's discretion per CONTEXT.md, this is the
  recommended default.

### Subscribe page sign-in/sign-out row (`src/pages.jsx`, `SubscribePage`)

Reused verbatim from the draft plan's Task 4 (260831-8ug-PLAN.md), which CONTEXT.md D-01
confirms as this phase's technical foundation. Placed directly above the billing-interval
toggle in the returned JSX:

```jsx
{authReady && (
  <div className="flex" style={{ justifyContent: "center", alignItems: "center", gap: 12, marginBottom: 24 }}>
    {!user ? (
      <>
        <span className="muted" style={{ fontSize: 13 }}>Members sign in with Google.</span>
        <button
          className="btn ghost"
          onClick={() => { window.location.href = "/api/auth/google?returnTo=subscribe"; }}
        >
          Sign in with Google
        </button>
      </>
    ) : (
      <>
        <span
          className="muted"
          style={{ fontSize: 13, maxWidth: 320, overflow: "hidden", textOverflow: "ellipsis", whiteSpace: "nowrap" }}
          title={user.email}
        >
          Signed in as {user.email}
        </span>
        <button className="btn ghost" onClick={handleSignOut}>Sign out</button>
      </>
    )}
  </div>
)}
```

- While `!authReady`, render nothing in this slot (same reasoning as the Nav element — see
  Copywriting/UI Considerations).
- Uses only existing classes: `.flex`, `.muted`, `.btn`, `.btn.ghost` — no new CSS required for
  this element beyond the truncation inline style shown above.
- `handleSignOut` POSTs to `/api/auth/logout` with `credentials: "same-origin"`, then calls
  `setUser(null)` (draft plan Task 4 behavior, unchanged by this contract).

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5).

**Elements classified:**
- E1 — Nav sign-in indicator: kind `nav` / `interactive-control`
- E2 — Subscribe page sign-in/sign-out row: kind `interactive-control`
- E3 — Sign-in failure path (triggered by E1/E2, resolved on return from Google): kind `interactive-control`

No `list-collection`, `form`, or `media` element exists in this phase's scope, so `empty`,
`populated`, `partial`, and `zero-one-many` are not raised by the relevance filter (all four
require one of those kinds).

Applicable state considerations resolved: 4 covered, 0 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Nav sign-in indicator (E1), Subscribe sign-in row (E2) | ✅ covered | While `!authReady`, both elements render nothing — no flash of "Sign in" before the signed-in state resolves (CONTEXT.md D-04; draft plan Task 4's `authReady` guard). |
| error | Nav sign-in indicator (E1), Subscribe sign-in row (E2), sign-in failure path (E3) | ✅ covered | A failed sign-in redirects silently to `/?auth=failed#subscribe` with the state cookie cleared — no visible error message or banner, by locked decision (CONTEXT.md D-07). See Copywriting Contract "Error state" row. |
| overflow | Nav sign-in indicator (E1) | ✅ covered | Signed-in Nav indicator truncates a long email/name via `.nav-signin`'s `max-width: 140px; overflow: hidden; text-overflow: ellipsis; white-space: nowrap` rather than wrapping or breaking the `.nav-right` flex row; full value exposed via `title` attribute. |
| long-text | Subscribe sign-in row (E2) | ✅ covered | Signed-in row's "Signed in as {email}" truncates the same way at `max-width: 320px` (more horizontal room than Nav), keeping the row on one line at all breakpoints ≥360px; full value exposed via `title` attribute. |

Not applicable (no `list-collection`/`form`/`media` element in this phase's scope): `empty`,
`populated`, `partial`, `zero-one-many`.

No `unclassified` elements — all three elements (E1, E2, E3) matched a clear kind from their
CONTEXT.md/draft-plan description.
