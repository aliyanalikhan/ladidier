# Phase 2 — UI Design Contract: Responsive Layouts

> Visual and interaction contract for the 480px phone breakpoint CSS pass.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Scope:** Pure CSS changes only — one standalone `@media (max-width: 480px)` block
> added after the 768px block in `styles.css`, plus a 480px override appended to
> `__TWEAKS_STYLE` in `tweaks-panel.jsx`. No React component logic changes.

## Spacing Scale

Phone-viewport spacing values used in the 480px pass. All multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Minimum gap (foot-base column gap at phone) |
| sm | 8px | foot-base gap: 8px (D-09, source: CONTEXT.md) |
| md | 16px | Horizontal padding override for article body and container (D-07); store-row grid gap (D-05); store-row vertical padding |
| lg | 24px | hero-manifest vertical padding bottom at phone |
| xl | 32px | tweaks panel left/right margin (calc(100vw - 32px) = 16px each side) (D-10) |
| 2xl | 48px | hero-manifest vertical padding top at phone |
| 3xl | 64px | — (not used at 480px; this is a desktop-scale value) |

Exceptions:
- Tap targets: 44px minimum height/width for all interactive elements (D-11) — not a spacing token but a minimum touch target constraint
- store-row number column: 32px (D-05) — derived from the compact grid column, not a spacing gap

## Typography

Phone-viewport overrides. All `clamp()` expressions from the base stylesheet are replaced
with explicit `px` values at 480px — no new clamp expressions.

Declared phone sizes: **16px** (body + lede), **22px** (H3 + store-row name), **30px** (H2), **40px** (H1) — exactly 4 distinct sizes.

| Role | Desktop (clamp base) | Phone override | Weight | Line height |
|------|----------------------|----------------|--------|-------------|
| Body / article prose | 18px (inline style) | 16px | 400 | 1.65 (override from 1.7) |
| Body / general | var(--sans) default | no change | 400 | var(--line-h) 1.45 |
| Lede / intro | clamp(18px, 1.5vw, 22px) | 16px | 400 | 1.5 |
| H1 display | clamp(48px, 9vw, 140px) | 40px | 300 | 0.92 |
| H2 display | clamp(36px, 6vw, 92px) | 30px | 300 | 0.95 |
| H3 display | clamp(24px, 3.2vw, 44px) | 22px | 300 | 1.1 |
| Store row name | clamp(28px, 3vw, 44px) | 22px (D-05) | 300 | 1 |
| Eyebrow / label | 11px | no change — already phone-legible | 400–500 | 1.4 |
| Buttons | 12px uppercase | no change | 600 | — |
| Footer links | 14px | no change | 400 | — |
| Marquee track | clamp(28px, 4vw, 56px) | no change — marquee hidden at 480px if inside .ticker; marquee in other contexts keeps default | 300 | — |

Declared font weights for this phase: 300 (display headings) and 400 (body). 600 used only for
button labels and eyebrow labels — a pre-existing constraint, not introduced in this phase.

## Hero — Decoration Stripping at ≤480px

Source: CONTEXT.md D-02, D-03, D-04.

| Element | Class | Treatment at ≤480px |
|---------|-------|---------------------|
| Store name marquee ticker | `.ticker` | `display: none` |
| SVG monogram watermark | `.watermark` | `display: none` |
| Floating ornaments | `.float`, `.float-slow` | `display: none` |
| Cursor gold halo | `.spotlight` | `display: none` |
| Magazine cover tilt | `.cover.tilt` | `transform: none; perspective: none` — removes 3D hover; renders as flat card |
| Hero-split portrait image | `.hero-split .ph` | `display: none` — split hero becomes text-only |
| Soft warm radial `.warmth` | `.warmth` | retained — low-cost background, not decorative noise |

Rationale: luxury brand voice at phone scale is delivered through typography, not layering.
Touch screens do not trigger `:hover` — 3D perspective effects are meaningless on phone.

## Layout Overrides at ≤480px

Source: CONTEXT.md D-05 through D-10.

### Footer (RESP-01)

```css
.foot { grid-template-columns: 1fr; gap: 32px; }
.foot-base { flex-direction: column; gap: 8px; align-items: center; text-align: center; }
```

### Hero — Manifest (RESP-02, Claude's discretion)

```css
.hero-manifest {
  padding: 48px 16px 24px;
  min-height: auto;         /* release the 78vh constraint at phone width */
  gap: 24px;
}
.hero-manifest .h1 { max-width: none; }   /* let text wrap naturally */
```

H1 renders at 40px (see Typography table). Text stacks cleanly without `max-width: 22ch` constraint.

### Hero — Split (RESP-03)

```css
.hero-split { padding: 48px 16px 32px; gap: 24px; }
.hero-split .ph { display: none; }   /* D-04 — text-only on phone */
```

Grid already collapses to 1 column at 920px; no grid override needed at 480px.

### Hero — Index (RESP-04)

```css
.hero-index { padding: 40px 16px; gap: 24px; }
```

Grid already collapses to 1 column at 920px; no grid override needed at 480px.

### Store rows (RESP-05)

```css
.store-row {
  grid-template-columns: 32px 1fr auto;   /* D-05 */
  gap: 16px;                              /* D-05 */
  padding: 16px 0;
}
```

`.store-row:hover` padding-inline expansion is disabled at phone (touch devices don't hover):

```css
.store-row:hover { padding-inline: 0; }
```

### Subscribe plan cards (RESP-06)

No CSS override required — base stylesheet uses `repeat(auto-fit, minmax(280px, 1fr))`.
At 480px the single column wraps automatically. If overflow is found during implementation,
add: `.plan-grid { grid-template-columns: 1fr; }`.

### Magazine article grid (RESP-07)

```css
.art-card { grid-template-columns: 1fr; }
/* Article grid container — target the parent with auto-fit columns */
/* Add class .art-grid if not already present; otherwise target inline grid */
```

Art cards: single column, full-width at 480px. The `.ph` image renders above the text.

### Article page body (RESP-08)

Article page uses an inline style on `<article className="container">`:
`padding: "64px var(--gutter)"` and `fontSize: 18, lineHeight: 1.7`.

Override in the 480px block:

```css
.container { padding-left: 16px; padding-right: 16px; }
```

This brings article horizontal padding to 16px as specified in D-07. The inline `fontSize`
and `lineHeight` on the article element cannot be overridden by a stylesheet rule — the
executor must either add a CSS class or accept that the phone uses 18px / 1.7 (acceptable
for reading). **Preferred:** add class `art-body` to the article element and declare:

```css
.art-body { font-size: 16px; line-height: 1.65; padding: 40px 0; }
```

If the executor cannot modify `pages.jsx`, use `.container` padding only and leave font
size at 18px (still readable; 16px is a refinement, not a requirement).

### Tweaks panel (RESP-09)

Source: CONTEXT.md D-10. CSS change goes into `__TWEAKS_STYLE` in `tweaks-panel.jsx`.

```css
@media (max-width: 480px) {
  .twk-panel {
    width: calc(100vw - 32px);
    right: 16px;
    left: 16px;
    transform-origin: bottom center;
    max-height: calc(100vh - 80px);   /* leave room for browser chrome */
  }
  .twk-hd { cursor: default; }       /* visual: remove move cursor on phone */
}
```

Drag is disabled visually by `cursor: default` on `.twk-hd`. If drag is implemented in JS
via pointer event listeners, those listeners should check `window.innerWidth > 480` before
activating. This is the only case where a JS media-query check is permitted (in the existing
drag handler, not a new component).

### Tap targets (RESP-10)

Source: CONTEXT.md D-11. 44×44px minimum for all interactive elements.

Phase 1 elements already compliant:
- `.nav-hamburger`: 44×44px (confirmed in styles.css)
- `.mobile-overlay-close`: 44×44px (confirmed in styles.css)

Elements requiring audit and override at 480px:

| Element | Current size | Phone fix |
|---------|-------------|-----------|
| `.btn` | 14px padding top/bottom → ~40px total | `min-height: 44px` |
| `.store-row` (entire row is tappable) | 28px padding each side → ~56px | already ≥44px |
| `.nav a`, `.nav button` | 18px nav padding → ~54px row | already ≥44px |
| `.subs-inline button` | 16px padding → ~43px | `min-height: 44px` |
| Footer links `.foot ul a` | line-height dependent | `min-height: 44px; display: flex; align-items: center` |
| `.mobile-overlay-link` | confirmed 44px from Phase 1 | no change |

```css
@media (max-width: 480px) {
  .btn { min-height: 44px; }
  .subs-inline button { min-height: 44px; }
  .foot ul a { min-height: 44px; display: flex; align-items: center; }
}
```

## Color Contract

No new colors introduced in this phase. The existing token palette applies unchanged.
Phone viewport uses the same color contract as desktop.

| Role | Token | Hex (light mode) | Usage |
|------|-------|-----------------|-------|
| Dominant (60%) | `var(--bg)` / `var(--ivory)` | #FFFFFF | Page background, surfaces |
| Secondary (30%) | `var(--bg-2)` / `var(--cream)` | #F6F4EF | Cards, footer background |
| Accent (10%) | `var(--gold)` | #B89358 | Focus outlines (nav-hamburger, overlay-close), `.foot ul a:hover`, `.btn.solid:hover` background, `.gold-text` headings |
| Foreground | `var(--fg)` / `var(--noir)` | #0A0807 | All body text, borders |
| Muted | `var(--mute)` | #8A8278 | Eyebrow labels, metadata, footer labels |
| Destructive | — | not applicable | No destructive actions in this phase |

Accent (`var(--gold)`) is reserved for: focus rings on interactive elements, link hover state
in footer, featured plan card shadow, `.btn.solid` hover fill. It is NOT used for body text,
borders, or backgrounds (except the `.warmth` radial gradient at ~14% opacity, which is ambient).
