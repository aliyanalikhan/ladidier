<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser devtools → Web Storage | The visitor can freely read and rewrite `ladidier_treasure_progress` (sessionStorage) and `ladidier_treasure_completed` (localStorage). There is no server to disagree with them. |
| Static source files → browser | `treasure.jsx` is served verbatim; `TREASURE_CODE` is readable via View Source by anyone, found or not. |
| JSX → DOM | All rendered content in this plan is author-written literals and hand-authored SVG. No visitor-supplied string, no URL parameter, and no storage value is ever rendered as content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | `ladidier_treasure_completed` (localStorage) | accept | A visitor can set it to skip the hunt or delete it to replay. Impact ceiling is cosmetic: the flag only controls whether four decorative icons render. It gates no content, no price, no access. Same accepted-limitation reasoning as Phase 5's `ladidier_perk_found`. Documented, not defended. |
| T-06-02 | Tampering | `ladidier_treasure_progress` (sessionStorage) | accept | A visitor can hand-write `["bag","box","tag","bow"]` to fake completion. The only prize is a static display-only string that is already public in the source. Building obfuscation for a non-secret is explicitly out of scope (REQUIREMENTS.md "Out of Scope": no backend, no validated codes). |
| T-06-03 | Information Disclosure | `TREASURE_CODE = "HOUSE20"` | accept | The code is visible via View Source without playing. It was never a secret — it is a promotional string with no backend validation, identical in kind to `HOUSE10`. No mitigation is appropriate; a fake-secret would be misleading. |
| T-06-04 | Tampering (XSS) | `TreasureIcon` / `TreasureProgress` render paths | mitigate | Enforced by construction: no `dangerouslySetInnerHTML` anywhere in `treasure.jsx`, and `readProgress()` values are only ever compared with `Array.prototype.includes` and counted with `.length` — never interpolated into markup, an `href`, or a `style` string. The verify gate asserts `grep -c dangerouslySetInnerHTML treasure.jsx` is 0. |
| T-06-05 | Denial of Service | `readProgress()` JSON.parse | mitigate | A visitor writing malformed JSON into `ladidier_treasure_progress` must not throw and white-screen the React tree. `readProgress()` wraps `JSON.parse` in try/catch and returns `[]` on any failure, and coerces non-array parse results to `[]`. |

Severity assessment: T-06-01/02/03 are LOW (cosmetic, no asset of value behind the boundary, no backend). T-06-04/05 are the only ones with a real failure mode (broken page) and both are mitigated by construction in this plan. Nothing in this plan reaches the "high severity — block" threshold.
