<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Web Storage → popup render path | `ladidier_subscribed` and the found-array both influence what the completion popup renders. Both are visitor-writable via devtools. |
| Popup → route navigation | The subscribe CTA calls `setRoute("subscribe")` with a hardcoded literal — no visitor-influenced destination. |
| CSS cascade → overlay stacking | `.treasure-reveal` is `position: fixed` at `z-index: 500`, overlaying page content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Tampering | `ladidier_subscribed` read in `TreasureHuntComplete` | accept | A visitor can set the flag to `"true"` to hide the subscribe CTA, or clear it to show one. The flag gates only which promotional copy renders; it grants no entitlement and this component never writes it. Identical accepted risk to Phase 5's PERK-05 branch, already shipped. |
| T-06-07 | Spoofing | `TREASURE_EVENT` CustomEvent | accept | Any script on the page (including a devtools paste) can dispatch `ladidier:treasure-found` with `complete: true` and force the popup open. The forged result is a card displaying a string already readable in View Source. There is no privileged action behind the event. Mitigating this would require a backend, which is out of scope per REQUIREMENTS.md. |
| T-06-08 | Tampering (XSS) | Completion popup content | mitigate | Every string rendered in the popup is an author-written literal or the `TREASURE_CODE` constant. No storage value, URL parameter, or visitor input is interpolated into markup. Enforced: no `dangerouslySetInnerHTML` in `treasure.jsx` (asserted in verification), and the `setRoute` argument is the hardcoded literal `"subscribe"` rather than any dynamic value. |
| T-06-09 | Denial of Service (self-inflicted UX) | `.treasure-reveal` fixed overlay | mitigate | A `z-index: 500` fixed card that could not be dismissed would trap the visitor and violate PERK-06's non-blocking rule. Mitigated by three independent dismissal paths (Close button, Escape key, outside click), no backdrop element, no scroll lock, and no focus trap — the page behind stays fully interactive. |
| T-06-10 | Elevation of Privilege | Discount code display | accept | `HOUSE20` confers a discount only if a human honours it off-platform. There is no redemption endpoint to elevate against. Explicitly out of scope: "Real, validated/redeemable discount codes" (REQUIREMENTS.md Out of Scope). |

Severity assessment: T-06-06, T-06-07 and T-06-10 are LOW — the asset behind each boundary is a public promotional string on a backend-less static site. T-06-08 and T-06-09 are the two with a genuine failure mode (script injection, trapped visitor) and both are mitigated by construction. No high-severity finding.
</threat_model>
