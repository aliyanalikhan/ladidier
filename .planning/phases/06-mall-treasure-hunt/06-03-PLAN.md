## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Static file server → browser | Three new `<script type="text/babel" src="treasure.jsx">` fetches, same-origin, no integrity attribute (matching every other first-party script tag in this project). |
| Third-party CDN → browser | Unchanged by this plan. React, ReactDOM and Babel remain pinned with existing SRI hashes. |
| Injected JSX → existing DOM | Three new component mounts inside `pages.jsx`, `components.jsx` and `app.jsx`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-11 | Tampering | New `treasure.jsx` script tag (no SRI) | accept | The file is first-party and same-origin; an attacker able to modify it already owns the deploy. Every existing first-party tag (`app.jsx`, `pages.jsx`, `components.jsx`, `perks.jsx`) is loaded the same way. Adding SRI to one first-party file while the other six lack it would be inconsistent theatre. The three third-party CDN tags keep their existing `integrity` hashes, untouched by this plan. |
| T-06-12 | Denial of Service | `Ladidier Portal-print.html` missing the script tag | mitigate | Omitting the tag makes `PrintApp` throw `ReferenceError: TreasureIcon is not defined` and render nothing — a total availability loss for the print view. Mitigated by requiring the identical insertion in both files in this same task, and asserted by a `<verify>` gate that checks both files' script order. |
| T-06-13 | Information Disclosure | Treasure icons leaking into printed/PDF output | mitigate | `PrintApp` renders all four target pages, so unsuppressed icons would appear in customer-facing print output. Mitigated by the four-selector `display: none !important` rule added to the print `<style>` block, following the existing `.twk-panel` and `.marquee` precedents. |
| T-06-14 | Tampering (XSS) | New JSX mounts | mitigate | All three mounts pass either a hardcoded string literal (`page="home"` etc.) or the app's own `go` function. No visitor-controlled value, URL fragment, or storage value crosses a mount boundary. Asserted by the exact-string `<verify>` greps. |
| T-06-15 | Elevation of Privilege | Route setter passed to the popup | accept | `TreasureHuntComplete` receives `go`, which can navigate anywhere in the SPA. Plan 02 constrains its only call site to the hardcoded literal `setRoute("subscribe")`. All routes are public marketing pages; there is nothing to elevate into. |

Severity assessment: T-06-12 and T-06-13 are the two with real user-visible impact (broken print view, icons in printed output) and both are mitigated in-task with automated gates. T-06-11, T-06-14 and T-06-15 are LOW on a backend-less static site with no authenticated surface. No high-severity finding.
