# Plan 08-01: Database DDL & Orchestration Seam

## Goal
Extend the `users` schema to track a linked Stripe Customer and build the safe, idempotent orchestration seam (`lib/account.js`) to find, create, and link customers while guarding against race conditions and duplicates.

## Requirements
- LINK-01: Starting checkout for a paid plan while signed in creates, or reuses, exactly one Stripe customer for that account — never a duplicate — via a UNIQUE `stripe_customer_id` column on `users`.

## Files to Edit

### 1. `lib/db.js`
- **Schema Update:** Append `alter table users add column if not exists stripe_customer_id text unique;` to the DDL in `ensureSchema()`.
- **Helpers:** Export `getUserById(id)` to retrieve a user row, and `setStripeCustomerId(userId, customerId)` to idempotently update `users set stripe_customer_id = $customerId where id = $userId and stripe_customer_id is null returning stripe_customer_id`.

### 2. `lib/account.js` (NEW)
- **`ensureStripeCustomer({ userId, email, name, stripe })`**:
  - Uses `getUserById(userId)`. Returns `stripe_customer_id` if present.
  - If null, creates a new Stripe Customer using `stripe.customers.create({ email, name, metadata: { user_id: String(userId) } }, { idempotencyKey: "create-cust-" + userId })`.
  - Saves the ID via `setStripeCustomerId`. If that update yields no rows (because a concurrent checkout won the race), re-reads `getUserById` and returns the winning ID.
- **`checkUserActiveMembership({ userId, stripe })`**:
  - Gets user's `stripe_customer_id`. Returns false if null.
  - Calls `stripe.subscriptions.list({ customer, status: 'all', limit: 5 })`.
  - Checks if any subscription's status is in `ACTIVE_STATUSES` (import `ACTIVE_STATUSES` from `lib/membership.js`).
  - Cache the status check per-serverless-instance for 60 seconds to respect Stripe limits.
