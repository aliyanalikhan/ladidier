# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder (per 10-CONTEXT.md D-02..D-04):** This phase ships a **functional-only, unstyled interim UI** — plain HTML buttons + a `<video>` element, positioned bottom-right in the final widget's approximate size/shape, with only the minimal CSS needed for correct positioning and basic usability. It does NOT deliver launcher chrome, category accordion, "Playing" badge, or luxury visual styling — all of that is explicitly Phase 11 scope (WIDGET-01..04, FAQ-01..03). It does NOT deliver reduced-motion/keyboard/ARIA/responsive polish or asset-failure fallback — that is explicitly Phase 12 scope (A11Y-01..05). This contract exists to pin down the interaction/state contract (video transitions, click affordances, z-index, mount sizing) that Phase 11 will build real chrome on top of without relocating.

## Spacing Scale

Declared values (must be multiples of 4), reusing this project's existing 8-point convention (see `.perk-reveal`, `.mobile-overlay` in `src/styles.css`):

| Token | Value | Usage this phase |
|-------|-------|-------------------|
| xs | 4px | Not used this phase |
| sm | 8px | Gap between question buttons within one category group |
| md | 16px | Widget container's outer edge offset (`right`/`bottom`); button internal padding |
| lg | 24px | Gap between category groups; mobile-breakpoint container inset (mirrors `.perk-reveal`'s `left/right/bottom: 16px` at ≤480px, and its unprefixed `24px` above that) |
| xl | 32px | Not used this phase |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- **44px minimum tap target** on every question `<button>` (`min-height: 44px`) — matches this project's existing sitewide convention (RESP-10), not a new rule invented for this phase.
- No other exceptions — this phase deliberately uses fewer of the scale's steps than a fully-styled UI would, per D-04's "minimal CSS only" boundary.

### Layout & Stacking (z-index) — required, not optional, per PITFALLS.md Pitfall 11

This project's current z-index vocabulary (verified directly in `src/styles.css`): `.mobile-overlay: 100`, `.reader-backdrop: 200`, `.perk-reveal` / `.treasure-reveal: 500`.

- **Widget container z-index: `40`.** Placed below `.mobile-overlay`'s `100` so opening the mobile hamburger nav correctly covers the widget, per PITFALLS.md's explicit recommendation. Document this value inline in `styles.css` next to the existing `.mobile-overlay: 100` / `.perk-reveal, .treasure-reveal: 500` comments, continuing the project's practice of keeping the z-index scale legible in one place.
- **Required pairing (functional, not visual):** when the mobile nav overlay opens, the widget's active `<video>` must be explicitly `.pause()`d — not merely visually covered — so no audio/video plays underneath the full-screen nav. This is a state-machine/effect requirement for this phase (reacts to the nav's existing open/close state), not a Phase 12 deferral.
- **Mount point:** `src/pages.jsx` → `HomePage` component (new `avatarFaq.jsx` import + one JSX sibling line), not `src/app.jsx` — inherits the existing `<main key={route}>` remount-on-navigate lifecycle for free (Pitfall 12/13).
- **Position/size (D-03 — "roughly like the final widget," not a throwaway test page):**
  - Desktop/tablet: `position: fixed; right: 24px; bottom: 24px; width: min(360px, calc(100vw - 48px)); max-height: min(600px, calc(100vh - 48px)); overflow-y: auto;`
  - Mobile (≤480px, mirroring `.perk-reveal`'s existing mobile override): `right: 16px; left: 16px; bottom: 16px; width: auto;`
  - This is the DOM position/footprint Phase 11 builds real launcher/accordion chrome on top of, per D-03 — Phase 11 must not relocate or restructure this mount point.

## Typography

Deliberately reduced ladder for this phase's unstyled scope (D-04) — full brand type ladder (Display/Heading treatments, editorial serif, etc.) is Phase 11 scope (WIDGET-03).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (question button text) | 16px | 400 (regular) | 1.4 |
| Label (plain category-group divider text) | 14px | 600 (semibold) | 1.2 |
| Heading | Not rendered this phase | — | — |
| Display | Not rendered this phase | — | — |

Notes:
- Exactly 2 sizes (16px, 14px) and 2 weights (400, 600) are declared — no more.
- Font-family for both rows: `var(--sans)` (inherited, no declaration needed in the interim markup).
- Heading/Display rows are intentionally empty: this phase renders no launcher title, no widget headline, and no "Playing" badge — those are Phase 11 (FAQ-02, WIDGET-03) additions layered onto this same DOM position.
- **No visual hierarchy is declared this phase, deliberately.** DOM/category order (the locked D-01 sequence) is the only ordering signal — no size, weight, or color differentiates one question button from another, and no element is styled to draw the eye first. Phase 11 (WIDGET-03) owns establishing real visual hierarchy on top of this same markup.

## Color

Deliberately minimal for this phase (D-04) — reuses only existing global CSS custom properties already defined in `theme.js`/`styles.css`; introduces zero new palette values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` (site white/ivory) | Widget container background — matches the page, no new surface color |
| Secondary (30%) | `var(--mute)` at border-only strength (`1px solid var(--mute)`) | The widget container's only visual separation from the page background — a plain thin neutral border for basic legibility, not a brand treatment |
| Accent (10%) | Not used this phase | See below |
| Destructive | Not applicable | No destructive actions exist in this phase |

Accent reserved for: **nothing in Phase 10.** The visible "selected/Playing" question state (FAQ-02) that would normally consume the brand's `--gold` accent is explicitly Phase 11 scope — adding it here would be inventing Phase 11 visual design ahead of schedule, which D-04 forbids. Question buttons in Phase 10 use only the browser/site default text color (`var(--fg)`, inherited) with no per-state color differentiation.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Each of the 15 locked FAQ question strings (10-CONTEXT.md D-01), used **verbatim** as its button's label text — no rephrasing, no abbreviation, no truncation. Category-group divider text also uses the 4 locked category labels verbatim: "About LaDidiér", "Shipping & Delivery", "Orders, Returns & Exchanges", "Payments & Customer Support". |
| Empty state heading | Not applicable — the FAQ question/category data is a locked, hardcoded constant (D-01); it can never be empty. See UI Considerations row below. |
| Empty state body | Not applicable — see above. |
| Error state | **"Tap to play"** — plain, unstyled text/button shown only if `video.play()`'s promise rejects (e.g. iOS Low Power Mode, per PITFALLS.md Pitfalls 1–2). Clicking it calls `.play()` again directly inside that click's event handler, preserving user-gesture attribution. This is a functional necessity this phase (without it, a blocked-autoplay visitor has no way to start the video at all) — not a polish item. |
| Destructive confirmation | Not applicable — Phase 10 has no destructive actions. |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).

Applicable state considerations resolved: 4 covered, 1 backstop, 0 unresolved, 4 dismissed (with reason)

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | FAQ question list (list-collection) | dismissed | 15 questions across 4 categories are locked, hardcoded static data (D-01) — the list can never be empty, so no empty state applies. |
| loading | Answer video / question buttons (media, interactive-control) | 🧪 backstop | Clicking a question with `preload="none"` may show a brief blank/black frame before the answer video's `.load()`+`.play()` resolves. No spinner/skeleton is added this phase (D-04: minimal CSS only) — the video is expected to start as soon as the browser can play it, with no other loading affordance. Verify at implementation time that this gap reads as "brief," not "broken." |
| error | Video playback autoplay-rejection (media) | ✅ covered | On `play()` promise rejection (`NotAllowedError`, e.g. iOS Low Power Mode), the plain "Tap to play" text/button (see Copywriting Contract) becomes visible and re-issues `.play()` from its own click handler. This is required functional behavior, not decoration — see PITFALLS.md Pitfalls 1–2. |
| error | Missing/failed video asset (media) | dismissed | A graceful fallback for a missing or corrupt video file is explicit Phase 12 scope (A11Y-05). Phase 10 accepts the browser's native broken-media rendering as a known, deliberately deferred gap — all 17 files are being freshly copied in this same phase (D-05/D-06), so the realistic risk is low. |
| populated | FAQ question buttons across 4 categories (list-collection) | ✅ covered | All 15 questions render as plain `<button>` elements grouped under 4 plain text category dividers, in the exact D-01 order, unconditionally — no accordion/collapse in Phase 10 (FAQ-03's accordion is explicit Phase 11 scope). |
| partial | FAQ question/category data (list-collection) | dismissed | Question/category data is a locked, hardcoded constant (D-01) defined entirely in `avatarFaqData.js` — it can never arrive partially populated. |
| overflow | Question list inside the fixed-size bottom-right container (list-collection, static-content) | ✅ covered | The question-list area gets `overflow-y: auto` inside the container's `max-height` cap (see Layout & Stacking), so all 15 buttons stay reachable by scroll without the container growing past its "approximate final widget size" (D-03). |
| zero-one-many | FAQ question buttons (list-collection) | dismissed | Always exactly 15 questions across exactly 4 categories per the locked D-01 data — no zero/one/many variability to design for. |
| long-text | Question button text (interactive-control) | ✅ covered | The longest question ("What should I do if my package says delivered, but I haven't received it?") wraps to multiple lines inside its button — no truncation/ellipsis. Buttons use normal text wrapping and an `auto`/growable height (not a fixed height), so the full question stays readable and clickable at every length in the locked set. |
