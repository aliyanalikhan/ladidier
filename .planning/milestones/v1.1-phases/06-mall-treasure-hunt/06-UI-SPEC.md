## Design System

| Property | Value |
|----------|-------|
| Tool | none — zero-build project (React 18 UMD + ReactDOM UMD + Babel-standalone via `<script>` tags, no npm/bundler). ## Spacing Scale

Declared values (must be multiples of 4), reusing the project's existing scale — no new spacing system introduced:

| Token | Value | Usage this phase |
|-------|-------|-------------------|
| xs | 4px | Gap between the 4 nav progress-dots |
| sm | 8px | Gap between stacked buttons in the completion popup's action row (mirrors `.perk-actions`) |
| md | 16px | Vertical rhythm between eyebrow / headline / code / body / actions inside the completion popup |
| lg | 24px | Completion popup outer left/right padding (reuses the same rounded value Phase 5 locked for `.perk-reveal`, `24px` not `28px`) |
| xl | 32px | Completion popup outer top/bottom padding — combined: `32px 24px`, identical shell to `.perk-reveal` |
| 2xl | 48px | Reserved, not used this phase |
| 3xl | 64px | Reserved, not used this phase |

Exceptions:
- Each `TreasureIcon` trigger `<button>` has a minimum **44×44px** hit area (site-wide RESP-10 convention, same as `.perk-mark`, `.nav-hamburger`), even though the visible icon graphic inside it is smaller.
- The visible icon glyph itself renders at **24px** (width/height) inside that 44px button — rounds RESEARCH.md's illustrative `size={22}` up to the nearest on-scale value. Intentional, deliberate rounding, mirroring Phase 5's own glyph-vs-hit-box exception note.
- Nav progress-dot indicator: each dot is an **8px** diameter circle, **4px** gap between dots (both on-scale). Total width for 4 dots ≈ `(4×8) + (3×4) = 44px` — deliberately sized to visually rhyme with the adjacent 44px `.nav-hamburger` button it sits beside in `.nav-right`.
- `z-index: 500` for `.treasure-reveal` (the completion popup) — same tier as `.perk-reveal`. The two mechanics never render simultaneously in normal use (a visitor completing the hunt has already dismissed any open perk panel), so sharing a tier is safe; this is a locked value for planning completeness, not a spacing value.

## Typography

Reuses existing type tokens from `styles.css` exclusively — no new sizes/weights invented, identical shell to Phase 5's `.perk-reveal` (Pattern 3: reuse `.paywall-gate`, don't reinvent).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label (eyebrow, e.g. "The House Treasure") | 11px, `--mono`, uppercase, `letter-spacing: var(--tracking-wide)` | 400 | 1.4 (matches `.eyebrow`) |
| Body (e.g. redemption line) | 15px, `--sans` | 400 | 1.5 |
| Heading (e.g. "You found the treasure!") | 20px, `--sans` | 400 | 1.2 |
| Display (discount code, e.g. "HOUSE20") | 24px, `--mono`, `.gold-text` gradient-clip | 600 | 1 |

Font weights used: **400 (regular)** and **600 (semibold)** — exactly 2, per contract rule. 600 is reserved for the discount code and button labels (`.btn` already uses `font-weight: 600`); everything else is 400.

Icon glyphs (bag/box/tag/bow) and nav progress-dots are not prose typography — their sizing is a Spacing concern (above) and their coloring is a Color concern (below), not a text role.

## Visual Hierarchy

Primary visual anchor of the completion popup: the discount code (`HOUSE20`), rendered at 24px `--mono` with the `.gold-text` gradient-clip treatment — identical role and treatment to Phase 5's `HOUSE10`. It remains the largest, highest-contrast, only gold-gradient text in the panel.

Treasure icons themselves are the **secondary** visual hierarchy concern of this phase and intentionally behave differently from Phase 5's perk mark: where `.perk-mark` sits at `opacity: .55` to stay "genuinely hard to find" (Phase 5's discoverability paradox), the 4 treasure icons render at **`opacity: 1`** (fully visible once positioned) with a subtle `transform: scale(1.08)` on `:hover`/`:focus-visible`. This is a deliberate, CONTEXT.md-mandated departure — Phase 6 is "a second, deliberately gamified discovery mechanic," not a subtle one. Difficulty comes from randomized per-page-load positioning (D-04) and needing all 4 across 4 pages in one session (D-09), not from visual camouflage.

## Color

Reuses existing `:root` custom properties from `styles.css:5-26` exclusively — **no new palette values** introduced, consistent with Phase 5's precedent and CONTEXT.md's overall "no new visual language beyond icon shape/color" framing.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` → `var(--ivory)` `#FFFFFF` | Site background behind icons/nav — unchanged |
| Secondary (30%) | `var(--cream)` `#F6F4EF` (`--bg-2`) | Completion popup surface, reusing `.paywall-gate`'s existing `background: var(--cream)` |
| Accent (10%) | `var(--gold)` `#B89358` | Reserved for exactly: (1) completion popup's 1px border (`.paywall-gate`'s existing border), (2) discount code text via `.gold-text` gradient, (3) nav progress-dot **filled** state, (4) all 4 icons' strap/string/outline detail strokes (ties every icon back to the house's gold identity), (5) icon/dot `:hover`/`:focus-visible` states. Never used for popup body copy or the Close button. |
| Icon multi-hue fills (NEW narrow use of existing tokens) | `var(--blush)` `#EFD7CC`, `var(--sage)` `#C9D2C0`, `var(--sky)` `#C7D2DE`, `var(--lilac)` `#DACDE0` | Reserved **exclusively** for the 4 treasure icons' primary fill color — one hue per icon, never mixed: `BagIcon` = blush, `GiftBoxIcon` = sage, `TagIcon` = sky, `BowIcon` = lilac. These 4 tokens already exist in `:root` (used today only for `.ph.blush/.sage/.sky/.lilac` photo-placeholder tints) and are unaffected by `applyTheme()`'s palette-switching (`app.jsx:34-45` only rewrites `--ivory/--cream/--noir/--gold/--accent`), so they stay visually stable and non-clashing across all 5 palettes + dark mode without introducing a single new color value. This is the mechanism satisfying D-02's "full-color, not monochrome-gold" requirement without inventing new hex values. |
| Destructive | N/A | No destructive actions exist in this phase (display-only reveal + click-to-collect icons, no delete/remove/cancel flows) |

Accent (`--gold`) reserved for: popup border, code text, nav-dot filled state, icon outline/strap strokes, hover/focus states. Icon multi-hue fills reserved for: exactly the 4 treasure-icon body fills, nowhere else in the UI.

Static, display-only, never inside a "redeem"/"validate"/"apply" UI (same accepted-limitation reasoning as `HOUSE10` — no backend exists to validate against). |

| Empty state | Not applicable — no data-driven empty state exists in this feature. The closest analog (an icon not yet found) carries zero explanatory copy before discovery, matching D-01's "genuinely gamified but not signposted with tooltips" framing. |
| Error state | Not applicable — no forms, no network calls, no validation (Security Domain V5: "No new user text input"). |
| Destructive confirmation | Not applicable — no destructive actions in this phase. |
