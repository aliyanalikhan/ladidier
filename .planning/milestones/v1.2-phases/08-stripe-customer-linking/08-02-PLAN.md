# Plan 08-02: Checkout Linking & API Routes

## Goal
Enforce that Stripe Checkout creates sessions attached to the exact `users.stripe_customer_id`, preventing duplicate Stripe customers from being minted. Provide the client with an API endpoint to retrieve the user's active membership status.

## Requirements
- LINK-01: Pass the durable Stripe customer ID to checkout sessions.
- LINK-04: Legacy entitlement files must remain unmodified.

## Files to Edit

### 1. `api/checkout.js`
- **Session Modification:** Before creating the Stripe checkout session, invoke `const customer = await ensureStripeCustomer({ userId: session.uid, email: session.email, name: session.name, stripe });`
- **Checkout Arguments:** Pass `customer` directly to `stripe.checkout.sessions.create({ customer, ... })`.
- **Remove `customer_email`:** Do *not* pass `customer_email` in the checkout session creation, as it will trigger Stripe to create duplicates.

### 2. `api/account/status.js` (NEW)
- **Endpoint:** `export async function GET(request)`
- **Session Parsing:** `const session = await readSession(request.headers.get('cookie'))`.
- **Unauthenticated Path:** If no session, return `Response.json({ active: false }, { headers: { 'Cache-Control': 'private, no-store' } })`.
- **Status Check:** If authenticated, call `checkUserActiveMembership({ userId: session.uid, stripe })`.
- **Response:** Return `Response.json({ active: boolean }, { headers: { 'Cache-Control': 'private, no-store' } })`.
