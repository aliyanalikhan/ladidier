# Plan 08-03: Client Integration & Phase Verification

## Goal
Surface the authenticated user's active membership status in the React client, ensuring cross-device digital edition unlocks, and verify the phase constraints against legacy files.

## Requirements
- LINK-02: User's membership status is read from the linked Stripe customer.
- LINK-03: Cross-device sign-in immediately unlocks membership.
- LINK-04: Legacy files (`api/entitlement.js`, etc.) remain byte-for-byte untouched.

## Files to Edit

### 1. `src/app.jsx`
- **Additive Membership Effect:**
  - Introduce a `useEffect` that triggers when `user` changes.
  - If `user` is non-null, fetch `GET /api/account/status`.
  - If `{ active: true }`, call `setIsMember(true)`. (Optionally write `"ladidier_member"` to `localStorage` to reflect the new state, but do *not* clear `localStorage` if false, so as not to break the legacy entitlement flow).
  - This ensures legacy cookies and account-based memberships are properly OR'd together.

## Verification Steps
1. **Schema Check:** Run `npm run db:setup` and verify `stripe_customer_id` is created.
2. **Build Check:** Run `npm run build` and ensure Vite succeeds.
3. **Legacy File Hash Check:** Ensure `git diff --quiet -- api/entitlement.js api/verify-session.js api/webhook.js lib/membership.js lib/stripe.js` remains completely clean.
4. **Integration Test:**
   - Sign in via Google.
   - Start checkout: Verify Stripe Checkout dashboard shows a linked Customer ID.
   - Pay (test mode): Verify subscription activates.
   - Sign in on a different browser: Verify `/api/account/status` returns `active: true` and UI grants access.
